# C. NodeSupervisor (надзор)

Уровень 4. Постоянный надзор инстансов Active-кластера: пересоздание
снесённых контейнеров, реакция на молчание, конвергенция лимитов, сбор
`usage`, восстановление адресов. Функция —
[02-cluster-lifecycle.md](../02-cluster-lifecycle.md) §4; модель —
[01-placement.md](../01-placement.md); принципы —
[17-synchronization-principles.md](../../17-synchronization-principles.md).

Сверка декларации с фактом docker + health-проба платформенной грани по
advertised-адресу. Journal — `op=supervise` со стационарной записью трека
молчания (`first_seen` по инстансам) и warning-ами тика.

- **Снесённый или остановленный контейнер** (положительное свидетельство
  инспекции: объекта нет либо он не `Running`; S7) → пересоздание на том же
  хосте с env из текущих секретов и PKI (`placed_on` фиксирован; volume
  сохраняется — данные и targets/cursors репликации не теряются),
  `state=PROVISIONING`; в `RUNNING` переводит следующий цикл по health.
- **Расхождение лимитов** живого контейнера (inspect: NanoCpus/Memory) с
  `nodes/<I>/resources` → пересоздание с лимитами декларации (docker не
  меняет лимиты живого контейнера; `disk` — инфо, не сверяется); при
  исчерпанном бюджете тика — journal-warning «расхождение отложено».
- **Одно пересоздание за тик** по любой причине; следующий кандидат — после
  возврата предыдущего в `RUNNING`.
- **Нода молчит** дольше `NodeDeadSec` при зрячей пробе (docker-факт
  прочитан, health-грань отвечает отказом) → `state=UNREACHABLE` БЕЗ
  деструктива (флап ≠ смерть); трек `first_seen` стартует/держится только
  по неуспешной пробе и снимается успешной; пересоздание по молчанию не
  выполняется — восстановит проба следующего тика либо docker-факт.
- **Слепая инспекция** (docker-хост молчит) — ошибка тика; пересозданий
  вслепую нет.
- **Отсутствие/битость secrets-ключа** — диагностическая запись надзора с
  отложенным пересозданием (env не собрать); значения секретов в
  диагностику не попадают.
- **Сбор `usage`** (гейт `HealthIntervalSec` по `updated_unix`; ошибка грани
  — warning, тик не фейлит) → ключ `nodes/<I>/usage`: квота-наблюдение
  `resources.disk` и алерты панели ([s3-clusters/02-keys.md](../../s3-clusters/02-keys.md)).
- **Переход в `RUNNING`** — по успешной health-пробе для любого инстанса
  (включая оставленный чужим provisioning: надзор идёт в тике раньше
  add-node).
- **Восстановление адреса** (лестница E9, до любых деструктивных действий):
  запись в portalloc → реконструкция из inspect живого контейнера
  (published-порт) с закреплением put-if-absent под `locks/portalloc` →
  ошибка тика, если восстановить нечего.
- **Нетронутые состояния**: `TO_REMOVE`, `REMOVING`, `NOT_INITIALIZED`;
  `PROVISIONING` чужого процесса — не пересоздаётся и лимитами не
  сверяется (чужая ответственность), но health-проба и `RUNNING` — работа
  надзора.

Состояния и переходы — [enums.md](enums.md).
