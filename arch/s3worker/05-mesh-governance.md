# S3Worker: доводка mesh

Уровень 3. Функция «доводка mesh»: приведение фактического состава
репликации инстансов к декларации `links` + `denylist`. Декларации и их
семантика — [s3-clusters/02-keys.md](../s3-clusters/02-keys.md); механика репликации ownS3 —
[owns3/07-replication.md](../../../OwnS3/arch/owns3/07-replication.md); полный
автомат — [G. MeshGovernance](processes/g-mesh-governance.md). Механизм —
этот же для фазы P4 provisioning ([A](processes/a-provisioning.md)).

## 1. Источник истины и факт

Источник истины — etcd (`links`, `denylist`, `nodes/<I>/pki`); факт —
админ-грань инстанса `GET /admin/replication/status` (состав target-записей).
Доводка идемпотентна, ретраи — тиками; структурные операции — не пачкой:
один инстанс/пара за тик.

## 2. Deny-доведение

Для каждого `RUNNING`-инстанса, КРОМЕ имён из `denylist` (отозванному
собственный список отзывов не нужен — изоляцию обеспечивают записи у его
соседей и запрет будущих join его сертификата), — полная перезапись
`PUT /replication/denylist` телом `{entries:[{name, publicKeyPem}]}` из
`denylist` кластера (ключи — из `nodes/<I>/pki`); подпись до-join контура —
сертификатом оркестратора (`pki/orchestrator`, схема OWNS3-PEER). Инстанс
недоступен — transient, следующий тик.

## 3. Сверка состава

Желаемые target-записи инстанса X = имена соседей по `links` минус
`denylist` минус несуществующие/не-`RUNNING` имена (связь с ещё
`PROVISIONING`-инстансом доводится после его `RUNNING`).

- **Недостающая связь {a,b}** → `POST /admin/replication/join`
  `{"endpoint": <b>}` на a (root-креды из secrets-ключа кластера —
  [04-security.md](04-security.md) §1; join двусторонний — обе стороны
  получают записи; курсор нового соседа −1 + reconcile-забор — механика
  ownS3). 409 (имя с другим ключом) → `DELETE` конфликтующей target-записи,
  ретрай следующим тиком; 403/502 — transient, ретрай.
- **Лишняя запись** (имя не в желаемых: убрана из `links`, deny, инстанс
  выведен) → `DELETE /admin/replication/targets/{name}` на каждой стороне
  пары (курсор сохраняется — возврат соседа продолжится с места).
- **Изоляция deny-инстанса**: связи с ним не джойнятся, существующие записи
  его имени у соседей и его собственные записи сносятся (имя не в желаемых).

Живость сторон перед join — по `state` (`RUNNING`) и health-факту надзора;
join к недоступному — transient-ретрай. Advertised-endpoint для join — из
portalloc ([01-placement.md](01-placement.md) §4).

## 4. Пределы

- **Full-mesh не инвариант**: доводка строит ровно заданный `links`
  (частичный/незеркальный состав нормален; зеркальность пары обеспечивает
  join-механика ownS3).
- Состав доводится только по декларации: полнота графа — ответственность
  оператора, зеркальность пары обеспечивает join ownS3; наблюдение
  связности/синхронности — зонд F ([06-sync-probes.md](06-sync-probes.md)).
- Диагностика — journal-фазы (`op=mesh-governance`: `idle`,
  `waiting-join`, отказ по инстансу) и метрики `mesh_*`
  ([08-operability.md](08-operability.md) §4).
