# D. WalSweeper (фоновая чистка `wal/`)

Уровень 4. Фоновый цикл гигиены префикса `wal/`: поглощённые финалом
`.partial`, устаревшие версии живого сегмента, сегменты ниже cutoff.
Функция — [07-retention.md](../07-retention.md) §3; ключи —
[05-etcd-contract.md](../05-etcd-contract.md).

Приёмники пишут объекты префикса `wal/` (`.partial`-версии и финальные
сегменты) в S3 напрямую, мимо воркера — устаревший мусор префикса
отслеживает и чистит САМ PgWorker (тот же, кто инициирует бэкапы). Исполняет
ТОЛЬКО глобальный лидер `/pgworker/leader` (паттерн orphan-sweeper)
отдельным ФОНОВЫМ циклом вне тиков управления/контроля: чистка не тормозит
ни клэймы, ни контроль цепи, ни планировщик полных.

Цикл идёт ПО КАЖДОМУ ШАРДУ НЕЗАВИСИМО — отказ/пауза одного шарда (S3-цель
недоступна, шард снесён) не останавливает остальные. Опрос и оценка
`.partial`-гигиены (поглощённые финалом `wal/<segment>.*.partial`,
устаревшие версии живого сегмента — остаётся длиннейшая, `.partial` ниже
cutoff) — НЕ РЕЖЕ раза в минуту по каждому шарду; срез финальных сегментов
ниже cutoff — тем же проходом по факту ретенционного отбора
([C](c-retention.md) §2).

Механика удаления: по шарду вычисляется полный список на удаление → ОДНИМ
batch-delete (повтор прохода идемпотентен). Наблюдаемость: живость цикла —
серия `worker_loop_last_success_timestamp_seconds{loop="wal-sweeper"}` плюс
per-shard свежесть последнего успешного прохода (алерт остановки цикла и
алерт просрочки отдельного шарда —
[metrics/README.md](../../metrics/02-dictionary.md) §2, паттерн OrphanSweepStalled);
`Backups:Enabled=false` → проход no-op, как ретенция.
