# Бэкапы: WAL-архивация и контроль цепочки

Уровень 3. Функция «WAL-архивация»: архитектура online-WAL (двойная
архивация), слоты, контроль непрерывности, `WAL_CHAIN_ERROR`/`gap`,
отставание и стоп-семантика. Механика приёмника на ноде —
[pgnode/03-wal-receiver.md](../pgnode/03-wal-receiver.md); ключи —
[05-etcd-contract.md](05-etcd-contract.md); состояния —
[processes/enums.md](processes/enums.md).

## 1. Архитектура

Приёмник WAL — процесс ВНУТРИ контейнера КАЖДОЙ ноды шарда (программа
`pgnode`, [pgnode/01-placement.md](../pgnode/01-placement.md) §1); стримят
только ноды-источники. Внутри — собственный .NET-приёмник: физическая
репликация (COPY-протокол `START_REPLICATION ... PHYSICAL` по слоту,
источник — `127.0.0.1:5432` своей ноды), приём XLogData, сборка сегментов в
памяти, при закрытии — put финального объекта `wal/<segment>`; до закрытия
— инкрементальная доотправка валидного префикса версиями
`wal/<segment>.<endLsn>.partial` каждые `Wal:PartialIntervalSec` (дефолт
3 с) и/или по порогу 4 МиБ (константа приёмника, не конфиг). Версия
выкладывается только ДЛИННЕЕ лучшей лежащей; финал поглощает версии;
`.partial`-версии чужих инкарнаций не гвардятся — их правило «длиннее
выигрывает» исключает конкурирующие байты по построению, а чужая
инкарнация ловится финальными объектами и непрерывностью цепи
([pgnode/03-wal-receiver.md](../pgnode/03-wal-receiver.md) §2).

**Двойная архивация (избыточность источника)**: инвариант нод
`synchronous_mode=true` — WAL подтверждённого изменения физически лежит в
`pg_wal` ОБЕИХ нод (мастер + sync-standby). Стримят приёмники ДВУХ
нод-источников — мастера и sync-standby (приёмник сам узнаёт роль
REST-пробой своей ноды); оба пишут в ОДИН префикс `wal/` шарда: имена
сегментов детерминированы (одинаковый WAL обеих нод), put идемпотентен —
дедупликация не нужна; контроль непрерывности склеивает union без
изменений. Дыра возможна только при потере одного и того же сегмента ОБИМИ
приёмниками — рестарты приёмников независимы, а с подтверждением-по-доставке
рестарт сегменты не теряет вовсе (защита детерминированная). Нет
sync-standby (переходное окно failover, single-нода) — стримит один
приёмник (мастер); приёмник новой sync-реплики включается сам при появлении
роли. Цена: ×2 стрим-трафик, ×2 буфер сегмента (память приёмников,
[09-operability.md](09-operability.md) §3). Граница RPO — доотправка
префиксов: sync-подтверждённый хвост выгружается `.partial`-версиями
каждые `Wal:PartialIntervalSec` (дефолт 3 с) — одновременная гибель всех нод
кластера теряет не более этого окна; незакоммиченные транзакции — вне
гарантий durable.

## 2. Слоты

Per-instance, имя `pgw_bkp_<C>_<X>` ОДНО И ТО ЖЕ на каждой ноде-источнике
(слоты разных PG-инстансов независимы — конфликтов нет); длиннее
NAMEDATALEN(63) → `pgw_bkp_` + sha1(`<C>/<X>`)[:16]. Слоты создаёт воркер
(SQL ensure идемпотентно: `pg_replication_slots` →
`pg_create_physical_replication_slot(..., true)`) на КАЖДОЙ ноде-источнике
(мастер + sync-standby) — удержание WAL на случай переключения/потери
второй стороны. Зонд слота источника — существование И `wal_status`:
существующий lost-слот лечится recreate (drop+create immediate+reserved), а
не пропускается ensure-идемпотентностью — стрим через инвалидированный слот
PG отвергает, «слот есть» ≠ «слот работает». Подключение — роль
`backup_exec` ([08-secrets.md](08-secrets.md)); ключ
`/clusters/<C>/backup_password` отсутствует (ensure не прошёл) → приёмник в
ожидании (`waiting_password`), стрима нет.

## 3. Контроль цепочки

Истина прогресса — объекты S3: воркер с периодом `Wal:VerifyIntervalSec`
делает union-листинг `wal/` по всем нодам пула, проверяет непрерывность от
`chain_start_segment` (правила имён/TLI, ratchet, `WAL_CHAIN_ERROR`, `gap`,
`DEGRADED`, отставание `lag_segments`/`Wal:StaleSec`) и пишет ключ `wal`.
Слоты ensure/recreate и лечение разрывов —
[B. WalChainControl](processes/b-wal-control.md).

## 4. Стоп-семантика

`Backups:Enabled=false` → глобальный ключ `/pgworker/backups-disabled` —
приёмники всех кластеров замирают; `STOPPED` — воркер сознательно остановил
поток живого шарда (эвакуация/карантин); демонтаж нод уносит приёмники, D2
чистит префикс `/pgworker/backups/<C>/`. Этими путями S3-объекты не
удаляются (удаляющие — ретенция, wal-sweeper, супервизор, `orphan-deletes`).
