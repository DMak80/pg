# Бэкапы: ретенция и гигиена хранилища

Уровень 3. Функция «ретенция и гигиена»: GFS-отбор, guard последнего
валидного, чистка WAL ниже cutoff, wal-sweeper, гейты мусора супервизора,
storage/quota и алерты. Процессы — [processes/c-retention.md](processes/c-retention.md),
[processes/d-wal-sweeper.md](processes/d-wal-sweeper.md),
[processes/e-supervisor.md](processes/e-supervisor.md); ключи —
[05-etcd-contract.md](05-etcd-contract.md).

## 1. Ретенция и гигиена

Ретенция полных — GFS по календарю UTC (дневные/недельные/месячные), guard
последнего COMPLETED, `DELETING` и гигиена FAILED; чистка WAL — сегменты
строго ниже cutoff последнего оставляемого verify-OK полного (гвард verify).
Фоновый wal-sweeper чистит `.partial`/финальные версии `wal/`; супервизор —
мусор `full/<id>/` живого шарда после двух гейтов, реестр сирот с DR-hold,
storage/quota и возрастные бюджеты операций. Процессы —
[C](processes/c-retention.md), [D](processes/d-wal-sweeper.md),
[E](processes/e-supervisor.md).

## 2. Алерты

**Суточный алерт**: панель вычисляет по снапшоту префикса — правило
`backup-full-stale` per-shard: возраст последнего ВАЛИДНОГО COMPLETED-полного
шарда (`verify.state ≠ FAILED` — OK/PENDING/отсутствует; проваленный verify
свежестью не считается) > `full_max_age_sec` политики кластера (policy-ключ
отсутствует → панельный дефолт 86400). Пустой префикс кластера (ни одного
ключа бэкапов — подсистема не включена) — правило молчит, ложных алертов на
выключенной подсистеме нет. Воркер алертов не пишет — только статусы (все
алерты панели — вычисления над снапшотом, как остальные правила AlertEngine).

**Алерт невалидного**: правило `backup-verify-failed` (critical) per-shard —
в статусе любого COMPLETED-полного `verify.state=FAILED` (описание —
`verify.error`: провал checksums / дыра цепочки с границами); воркер
реагирует переснятием (планировщик не считает проваленный verify свежестью),
действие оператора — разбор по runbook. Проверки по политике:
`verify.on_create` — сразу после COMPLETED, `verify.interval_sec` —
периодическая перепроверка каждого оставшегося COMPLETED-полного по возрасту
`verify.checked_unix` (тихая порча/утеря объектов S3).

## 3. Deprovisioning и сироты

Deprovisioning кластера (D2) чистит etcd-префикс
`/pgworker/backups/<C>/` тем же `del --prefix` (идущие операции бэкапов
уходят вместе с нодами шарда — D1 сносит контейнеры нод с приёмниками;
отдельных контейнеров/джобов бэкапов нет); объекты S3 этим путём НЕ
удаляются (данные дороже места; осознанное удаление — только ретенция по
политике): префикс S3 без etcd-владельца попадает в реестр сирот
`/pgworker/backups/orphans` супервизора — алерт панели + удаление по
`Supervisor:OrphanTtlSec` (гибрид: мусор живого шарда — `full/<id>/` без
ключа — удаляется per-cluster-проходом после гейтов
[E](processes/e-supervisor.md) §1; исчезнувшие
владельцы — реестр+TTL; DR-hold: TTL чистит только незащищённых — валидный
полный или hold держат префикс до явной заявки `orphan-deletes`);
восстановление удалённого кластера из S3 — runbook backup-restore (воркер не
уничтожает потенциально ценные данные автоматикой).
