# C. SnapshotExport (DR-слепки, выгрузка, обслуживание)

Уровень 4. Плановое и внеочередное снятие слепков etcd, выгрузка в
etcd-backup кластер, доводка отставания и обслуживание контура. Функция —
[04-snapshots.md](../04-snapshots.md); формат объектов и статус-ключа —
[00-etcd-contract.md](../00-etcd-contract.md) §3,
[backups/06-s3-layout.md](../../backups/06-s3-layout.md).

Исполняется лидерным `SnapshotLoop` (singleton-цикл; второй исполнитель
исключён). Journal не ведётся — носитель состояния цикла: статус-ключ
`/etcdworker/snapshots` и локальный том.

```
C0 лидерство: лидер — тик; не лидер — попытка захвата и сон ScanIntervalSec
C1 доводка отставания ДО снятия (CatchUp): отставание — по СТАТУС-ключу
   (FAILED, либо ключа нет, либо новейший локальный снят позже
   подтверждённого покрытия); новейший локальный слепок перечитывается и
   уезжает конвейером C3 (промежуточные — нижние ревизии того же ряда)
C2 решение снятия (чистая функция расписания): плановый раз в IntervalMin;
   внеочередной — revision выросла и последняя выгрузка старше
   MinIntervalSec; нет — тик успешен (ошибка прошлого тика гасится)
C3 снятие: SnapshotJob (/v3/snapshot/save, failover по endpoints) →
   локальный том /snapshots (ретенция RetentionFiles) → чтение байтов →
   ExportAsync:
     живой резолв цели (единственный /s3/clusters/<C> с etcd_backup=true →
     endpoints + secrets.backups) и S3-клиент per-попытку;
     put etcd/snapshot-<id>.db (SHA256-проверка транспорта) →
     put etcd/snapshot-<id>.meta.json → ретенция N пар (guard ≥1) →
     put статус-ключа OK (покрытие = метка снятия, не заливки);
     всё под единым бюджетом TimeoutSec, S3-шаги — с пульсом;
     любая неудача → статус FAILED + error (поля успеха сохраняются),
     цикл Failed — короткий сон RetryIntervalSec
C4 обслуживание контура: compact + defrag каждой ноды последовательно, не
   чаще MaintenanceIntervalMin; отказ — warning, тик не фейлит
C5 повторный расчёт отставания ПОСЛЕ снятия: первый транзиент мог увести
   статус в FAILED уже после расчёта «до» — иначе цикл ушёл бы в длинный сон
   с невыгруженным слепком; отставание → сон RetryIntervalSec, иначе —
   ScanIntervalSec
```

Все шаги идемпотентны (put поверх; коллизия имён в одну секунду — новее
поверх). Отказ выгрузки — домен статус-ключа, НЕ цикл: снятие прошло, слепок
в локальном томе, цикл здоров; панельный алерт по `FAILED`.

Помимо выгрузки цикл снимает слепки не чаще расписания — «слепок в тишине не
снимается»: RPO держится детекцией изменений (C2), а не частым снятием.
