# EtcdWorker: надзор managed-узлов

Уровень 3. Функция «надзор»: наблюдение живости узлов, восстановление
окружения и снос осиротевших объектов. Полный автомат —
[B. NodeSupervisor](processes/b-node-supervisor.md); модель —
[01-placement.md](01-placement.md); состояния —
[processes/enums.md](processes/enums.md).

Надзор — не самостоятельный цикл: он исполняется в тике доводки состава под
лидер-клэймом, до и после `MembershipProcess`
([06-operability.md](06-operability.md) §1).

## 1. Наблюдение

- **Health-проба** каждой клиентской грани (`/v3/maintenance/status` по
  client-порту из portalloc; не чаще `HealthIntervalSec`). Проба — исполненная
  итерация наблюдения: между узлами отмечается прогресс цикла (серия
  таймаутящихся проб не должна выглядеть зависанием).
- **Проблема** фиксируется по факту `unstarted`-члена ИЛИ молчания грани;
  метка ПЕРВОГО наблюдения запоминается и сбрасывается успешной пробой.
  Гейт пробы закрыт (проба была недавно) — факта нет, метка не ставится.
- **Молчание** дольше `NodeDeadSec` → `state=UNREACHABLE`; успешная проба
  возвращает `UNREACHABLE` → `RUNNING`. Деструктивных действий по факту «не
  отвечает» нет (S7: флап ≠ смерть) — материал для авто-замены собирается
  комбинацией свидетельств ([02-membership.md](02-membership.md) §4).
- **Слепая проба** (хост молчит) — никаких действий и никаких фактов.
- Наблюдение отдаёт факты проблем (член, с какого момента, отсутствует ли
  окружение) — вход авто-замены.

## 2. Восстановление окружения (repair)

Один шаг за тик, только для узлов в состояниях `RUNNING`/`UNREACHABLE`,
присутствующих в составе и с закреплённым портом (остальные состояния и
узлы без члена не трогаются — их ведёт свой процесс):

- **Контейнер отсутствует или не работает** (положительное свидетельство
  docker-инспекции) → пересоздание с закреплённым портом и сохранённым
  volume: member возвращается с теми же данными; state `PROVISIONING` →
  `RUNNING` по факту подъёма.
- **Расхождение client-порта** живого контейнера с закреплением (чужая
  публикация) → снос контейнера (volume жив) и пересоздание с портом
  portalloc.
- Состав перечитывается НА МОМЕНТ решения: если доводка этого же тика вывела
  члена, repair не «воскрешает» узел по устаревшему снимку.

## 3. Снос осиротевших объектов (orphan-cleanup)

Объекты `etcdw-node-*` (label `etcdworker`), чей номер НЕ имеет члена в
составе, сносятся вместе с volume, portalloc освобождается. Это штатный
путь возврата хоста после авто-замены: осиротевший data-dir удалённого члена
etcd сам отверг бы на старте.

Состав и объекты перечитываются НА МОМЕНТ решения (снимок начала тика
устаревает: свежеподнятый узел того же тика иначе сносился бы как сирота —
bootstrap-дедлок кворума); нечитаемый состав — мусорщик молчит (снос без
факта небезопасен). Journal-фаза `orphan-cleanup`.

## 4. Инварианты

- **Один repair-шаг за тик**; слепая docker-проба — никаких действий.
- Тома надзор не уничтожает, кроме доказанного сиротства (нет члена в
  составе) — данные живого члена неприкосновенны.
- Надзор не меняет состав: вывод/добавление членов — только
  `MembershipProcess` ([02-membership.md](02-membership.md)).
