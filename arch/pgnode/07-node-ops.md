# PgNode: операции ноды

Уровень 3. Вспомогательные операции, исполняемые тем же процессом:
`pg_dump` схемы, проба данных ноды, обеспечение pg_hba. Потребители —
PgWorker ([pgworker/README.md](../pgworker/README.md) §4); секреты —
[backups/08-secrets.md](../backups/08-secrets.md) §4.

## 1. `pg_dump` схемы (`POST /api/node/pgdump`)

DDL-перенос переезда бакета: воркер командует приёмнику ноды-источника
([pgworker/processes/f-move.md](../pgworker/processes/f-move.md) §3 M1);
приёмник снимает `pg_dump --schema-only` локально в контейнере ноды
(локальный socket-коннект, без передачи секретов) → результат применяется на
приёмнике → гранты app → сверка инвентаря. Отдельного контейнера/джоба нет;
операция живёт в общем процессе.

## 2. Проба данных ноды (`POST /api/node/pgdata`)

Проверка `PG_VERSION` файловой системой своего контейнера → ответ
`Present`/`Absent`/`Unknown` (транспортный отказ). Используется в лечении
HA-scope при доказанной утрате данных
([pgworker/processes/a-provisioning.md](../pgworker/processes/a-provisioning.md)
P2.2): чистка scope — только при `Absent` у ВСЕХ нод; `Present` или
`Unknown` — не лечить. Отдельного процесса/контейнера нет.

## 3. Обеспечение pg_hba (`POST /api/node/hba-ensure`)

Строка `hostssl replication backup_exec all scram-sha-256` нужна для
физического WAL-стриминга под `backup_exec` (дефолтный Spilo-pg_hba
разрешает replication только роли `standby`). Владелец строки — приёмник в
своём контейнере; два канала обеспечения:

- **самообеспечение** — цикл подключения приёмника перед каждой попыткой
  сессии/инвентарного прохода выполняет ту же операцию локально
  (идемпотентно: строка на месте — один file-read, без SIGHUP); замыкает
  окно «свежеподнятая нода начала стрим раньше первого тика воркера»;
- **гвард G2 воркера** — каждый тик командует `POST /api/node/hba-ensure`
  каждой ноде шарда; приёмник добавляет строку в ИСТОЧНИК конфига Patroni
  `/run/postgres.yml` (секция `postgresql.pg_hba`) и будит Patroni SIGHUP'ом
  — тот сам перегенерирует `pg_hba.conf` при каждом старте postgres
  (правка самого `pg_hba.conf` бессмысленна: файл перегенерируется Patroni).
  Ожидание применения — поллинг `$PGDATA/pg_hba.conf` (нода без PG_VERSION
  ещё бутстрапится — ждать нечего, строка применится при первом старте).
  Отказ операции — transient: шард skip, следующий тик дообеспечит (запуск
  на непатченной ноде карался бы FAILED-циклом с бэкоффом).
