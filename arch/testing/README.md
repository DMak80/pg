# Тестирование: E2E-контур

Уровень 2. Сквозные правила работы с docker-E2E тестами — единые для всех
E2E-проектов монорепо (`src/tests/{PgWorker,KafkaWorker,ValkeyWorker,
S3Worker}.E2eTests/`). Раздел описывает **как устроен и запускается
E2E-контур**, а не отдельные сценарии: архитектура окружения, изоляция,
телеметрия, порядок разбора падений.

## Документы

| Документ | Содержание |
|---|---|
| [01-e2e-launch.md](01-e2e-launch.md) | правила запуска и телеметрии: статика, полные логи, фазы >60 с, падение и перезапуск, параллелизм, отчётность |
| [02-e2e-isolation.md](02-e2e-isolation.md) | принципы изоляции: единица окружения, динамические порты, SUT-контейнер, own-only чистка, teardown, порт-план, чек-лист сценария |

Команды сборки и запуска серий — операционный runbook
[operations/04-e2e-runs.md](../operations/04-e2e-runs.md).

## Границы

- Раздел описывает **E2E-контур** (docker, класс-фикстура, реальные
  контейнеры). Юнит- и интеграционные тесты живут по правилам своих
  проектов; общие требования к тестам — [AGENTS.base.md](../../../AGENTS.base.md)
  (вне репозитория).
- Правила изоляции и запуска — **обязательные**: расхождение E2E-кода с
  ними — блокирующее замечание ревью.
- Сценарии и их данные — в тестовых проектах; здесь только сквозной канон.

## Применение

- Новый E2E-сценарий проектируется по [02-e2e-isolation.md](02-e2e-isolation.md)
  (чек-лист в конце документа).
- Прогон и разбор падения — по [01-e2e-launch.md](01-e2e-launch.md);
  команды — [operations/04-e2e-runs.md](../operations/04-e2e-runs.md).
- Правило первично: если реализация с ним расходится, правится реализация,
  а не правило.
