# S3-кластеры: модель размещения

Уровень 3. Как хост описывается атрибутами и как placement-селектор
превращается в фактическое размещение инстанса. Ключи `placement`/
`placed_on` — [02-keys.md](02-keys.md) §1; поведение воркера —
[s3worker/01-placement.md](../s3worker/01-placement.md).

## 1. Хост — набор атрибутов

- **plain** — атрибут `docker_host`: имя из таблицы
  `S3Worker:Docker:Hosts[]` воркера
  ([s3worker/01-placement.md](../s3worker/01-placement.md) §1).
- **swarm** — атрибуты `swarm_node` (hostname ноды swarm) и `swarm_labels`
  (`node.labels.*` — произвольные пары ключ-значение, в т.ч. гео-метки
  площадок).

## 2. Привязка инстанса = предикат

`placement`-селектор — конъюнкция равенств по атрибутам. Инстанс кластера
ОБЯЗАН иметь селектор (валидация API: пустой или невалидный — 400,
[s3worker/07-api.md](../s3worker/07-api.md) §3).

## 3. Резолюция

Выполняет воркер в фазе provisioning/add-node:

- по селектору — список кандидатов-хостов;
- **ноль кандидатов** — transient-фейл фазы (journal, ретрай тиком: хост
  может появиться в конфигурации);
- **несколько кандидатов** — детерминированный выбор (least-loaded по числу
  занятых портов/тасков, tie-break по имени; journal-запись с перечнем
  кандидатов);
- результат — `placed_on`; повторные проходы идемпотентны (тот же хост, пока
  селектор не изменён выводом инстанса).

## 4. Анти-аффинити

По отношению к другим инстансам того же кластера **автоматикой НЕ
вводится**: разнос по площадкам — обязанность оператора (гео-схема — явные
селекторы). Канон фиксирует рекомендацию «инстансы одного кластера — на
разных хостах/площадках» и индикацию совпадений панели.

## 5. Смена привязки

Перепривязка живого инстанса на месте не допускается (данные тома привязаны
к хосту): смена привязки — вывод инстанса и добавление нового
([s3worker/03-node-scaling.md](../s3worker/03-node-scaling.md) §1–§2).
