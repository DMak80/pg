# C. SnapshotExport (DR-слепки, выгрузка, обслуживание)

Уровень 4. Плановое и внеочередное снятие слепков etcd, выгрузка в
etcd-backup кластер, доводка отставания и обслуживание контура.
Исполнитель — агент-ЛИДЕР EtcdNode (singleton-цикл; второй исполнитель
исключён). Функция — [../02-snapshots.md](../02-snapshots.md); формат
объектов и статус-ключа — [../00-etcdnode-contract.md](../00-etcdnode-contract.md) §3,
[../../backups/06-s3-layout.md](../../backups/06-s3-layout.md); модель
агента — [../01-agent.md](../01-agent.md).

Journal не ведётся — носитель состояния цикла: статус-ключ
`/etcdnode/snapshots` и локальный том своего узла.

```
C0 лидерство: лидер (клэйм /etcdnode/leader) — тик; не лидер — попытка
   захвата и сон скана
C1 доводка отставания ДО снятия (CatchUp): отставание — по СТАТУС-ключу
   (FAILED, либо ключа нет, либо новейший локальный СВОЕГО узла снят
   позже подтверждённого покрытия); новейший локальный слепок
   перечитывается и уезжает конвейером C3
C2 решение снятия (чистая функция расписания с фильтром важности):
   плановый раз в IntervalMin; внеочередной — есть ВАЖНОЕ изменение
   (revision вырос → полный range → дифф с эталонной картой: изменён/
   появился/исчез ключ ВНЕ списка пульсов; нет эталона — важно) И
   последняя выгрузка старше MinIntervalSec; изменения только в пульсе —
   снятия нет, тик успешен (ошибка прошлого тика гасится)
C3 снятие: /v3/snapshot/save на http://localhost:2379 → локальный том
   /snapshots (ретенция RetentionFiles) → чтение байтов → ExportAsync:
     живой резолв цели (единственный /s3/clusters/<C> с etcd_backup=true
     → endpoints + secrets.backups) и S3-клиент per-попытку;
     put etcd/snapshot-<id>.db (SHA256-проверка транспорта) →
     put etcd/snapshot-<id>.meta.json → ретенция N пар (guard ≥1) →
     put статус-ключа OK (покрытие = метка снятия, не заливки) И
     эталонная карта = range этого момента;
     всё под единым бюджетом TimeoutSec, S3-шаги — с пульсом;
     любая неудача → статус FAILED + error (поля успеха сохраняются),
     цикл — короткий сон RetryIntervalSec
C4 обслуживание контура: compact + defrag каждого члена последовательно
   (client-грани из member list), не чаще MaintenanceIntervalMin;
   отказ — warning, тик не фейлит
C5 повторный расчёт отставания ПОСЛЕ снятия: первый транзиент мог увести
   статус в FAILED уже после расчёта «до» — иначе цикл ушёл бы в длинный
   сон с невыгруженным слепком; отставание → сон RetryIntervalSec, иначе —
   сон скана
F  отказ localhost (свой etcd недоступен): тик работу не исполняет
   (warning); статус НЕ пишется, лидерство НЕ релизится — координация
   localhost-only ([../01-agent.md](../01-agent.md) §2): lease гаснет по
   TTL ≤ 15 с, работу и статус пишет новый лидер (экспортёр несёт полный
   список endpoints тика)
```

Все шаги идемпотентны (put поверх; коллизия имён в одну секунду — новее
поверх). Отказ выгрузки — домен статус-ключа, НЕ цикл: снятие прошло,
слепок в локальном томе, цикл здоров; панельный алерт по `FAILED`.

Помимо выгрузки цикл снимает слепки не чаще расписания — «слепок в тишине
не снимается»: RPO держится детекцией ВАЖНЫХ изменений (C2), а не частым
снятием.
