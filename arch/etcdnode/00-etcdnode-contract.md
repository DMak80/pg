# EtcdNode: контракт домена `/etcdnode/`

Уровень 3. Ключи домена EtcdNode, их форматы, писатели и инварианты
записи. Модель агента — [01-agent.md](01-agent.md); функция слепков —
[02-snapshots.md](02-snapshots.md). Layout объектов слепков в S3 —
[backups/06-s3-layout.md](../../backups/06-s3-layout.md) (без изменений).

## 1. Ключи

| Ключ | Формат | Пишет | Назначение |
|---|---|---|---|
| `/etcdnode/leader` | lease TTL 15 с | агент | лидер singleton-цикла слепков (один исполнитель на контур) |
| `/etcdnode/instances/<k>` | lease TTL 15 с, значение — `etcdw-node-<k>` | агент | живость агентов (k — номер узла; наблюдаемость) |
| `/etcdnode/snapshots` | JSON `{"state":"OK"\|"FAILED","last_uploaded_unix"?,"last_object"?,"last_sha256"?,"size_bytes"?,"interval_min"?,"error"?}` | агент-лидер (исполнитель выгрузки) | статус DR-выгрузки (семантика покрытия — §3) |

Панель читает `/etcdnode/snapshots`
([adminpanel/02-etcd-contract.md](../adminpanel/02-etcd-contract.md));
лидер-клэйм и живость — наблюдаемость диагностики. Unknown-ключи — не
ошибка (толерантные парсеры).

## 2. Инварианты записи

- **Единственный писатель домена**: `/etcdnode/` пишут ТОЛЬКО агенты
  EtcdNode (каждый — ключ живости своего `<k>`; лидер — клэйм и статус).
  EtcdWorker домен не пишет.
- **Лидерство** — txn-захват `version==0` под lease TTL 15 с; потеря
  lease прерывает тик (cancellation-гвард), клэйм переходит ≤ TTL + тик
  скана. Снятие слепка и запись статуса — только лидер.
- **Статус** — put поверх с семантикой покрытия (§3); неудача выгрузки
  обязана доехать до статуса `FAILED` (алерт панели).
- Значимое состояние цикла — ключи домена + локальный том слепков;
  журнал фаз НЕ ведётся (все шаги идемпотентны, носитель возобновляемости
  — статус-ключ и факт объектов в S3).

## 3. Статус DR-выгрузки

- `state` — `OK` (последняя выгрузка успешна) либо `FAILED` (сообщение —
  в `error`, поля последнего успеха сохраняются).
- `last_uploaded_unix` — метка **покрываемого** слепка (время снятия, не
  время заливки): инвариант отставания сравнивает её с новейшим локальным
  слепком узла; фактическое время заливки живёт только в `.meta.json`
  (`uploaded`).
- `last_object` — объект последней выгрузки, реально лежащий в S3;
  `last_sha256` — наблюдаемость (в решении о записи не участвует).
- `interval_min` — эффективный плановый интервал для панельного
  stale-алерта (2× интервала).
- Поле `enabled` НЕ пишется: выгрузка безусловна, «не настроено» отражает
  `FAILED` с маркером `etcd-backup-missing` ([02-snapshots.md](02-snapshots.md) §1).

## 4. Читаемые ключи чужих доменов

Агент читает (и никогда не пишет) `/s3/clusters/<C>/{config,endpoints,secrets}`
etcd-backup кластера: признак `etcd_backup=true`, адреса инстансов и креды
ключа `backups` — живой резолв цели на каждую попытку выгрузки
([02-snapshots.md](02-snapshots.md) §1). Ключ `backups` для etcd-backup
кластера содержит спец-ключ из env S3Worker
([s3worker/04-security.md](../s3worker/04-security.md) §1).
