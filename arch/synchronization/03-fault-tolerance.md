## S7. Транспортный флап ≠ смерть: деструктив — только по положительному свидетельству

**Правило.** «Не отвечает» — НЕ свидетельство смерти. Деструктивные
действия (снятие лидер-ключа Patroni, пересоздание ноды, эвакуация)
допускаются только по **положительному свидетельству**: docker-объект
отсутствует **или** контейнер не-running по инспекции. Причём инспекция
обязана быть **честной**: если драйвер не умеет running-инспекцию
(заглушка Swarm), свидетельство «узла нет в списке» **не считается** —
ветка гейтится capability (`SupportsRunningInspection`), промоушен
остаётся на lease/loop_wait Patroni.

**Почему критично.** Ложное «смерть» по флапу на живом лидере → снятие
leader-ключа → лишний failover продакшн-кластера: доступность роняется
средством её защиты.

**Кейс.** Заглушка `SwarmClusterDriver.InspectNodesAsync`
возвращает пустой список: «пусто = не running» дало бы ложный failover в
Mode=Swarm по любому флапу пробы. Фикс: capability-гейт
([pgworker/processes/c-node-supervisor.md](../pgworker/processes/c-node-supervisor.md))
+ unit-инверсия (no-inspection → ускорения нет).

**Проверка.** Unit-инверсия на каждом деструктивном пути: «источник
свидетельства врёт/пуст → действия НЕТ».

**Endpoint-failover etcd: sticky последнего живого + per-attempt бюджет +
негативный кэш мёртвых** (единая точка `Shared.Etcd.Client.EtcdEndpointFailover`;
дубликаты цикла обхода запрещены). Мёртвый IP члена кластера — «чёрная
дыра» транспорта (SYN висит до TCP-таймаута, порядка секунд): последовательный обход
платит этот штраф КАЖДЫМ вызовом, пока список начинается с мёртвого —
lease-продления опаздывают, ключи с TTL кратковременно гаснут (факт стенда
ha-etcd). Поэтому: следующий вызов начинается с ПОСЛЕДНЕГО ответившего endpoint,
каждая попытка ограничена бюджетом (мёртвый endpoint отрезается, контроль —
следующему), ротация старта от вызывающего (startIndex ≠ 0) имеет приоритет
над sticky.

**Негативный кэш обязателен, sticky его не заменяет.** Sticky ключуется
полной строкой списка, а один процесс ведёт НЕСКОЛЬКО списков (клэйм, журнал,
instance-ключ, health-проба — факты прогона ha-etcd: три вызова трёх списков
в одной фазе тика, каждый начал обход с одного и того же мёртвого узла) —
без общей карты каждый список платит штраф своим первым после-смерти вызовом,
и серия таких штрафов внутри одной фазы (grant → txn → put) растягивает тик
за порог watchdog (слепая зона,
[pgworker/08-operability.md](../pgworker/08-operability.md) §3). Правило:
неуспешная попытка (исчерпан бюджет попытки, транспорт-отказ) помечает endpoint в
ПРОЦЕСС-ГЛОБАЛЬНОЙ карте мёртвых на cooldown = 3 бюджета попытки; обход
ЛЮБОГО списка пропускает помеченные (все помечены — обычный обход по кругу);
первый успех снимает пометку. Sticky — оптимизация порядка; негативный кэш —
общая защита от повторной оплаты уже известной смерти.

**Проверка.** Unit: второй вызов с другим списком не стартует с помеченного
мёртвого (штраф платится один раз на смерть, не на список); успех снимает
пометку; все помечены — обход не блокируется.
