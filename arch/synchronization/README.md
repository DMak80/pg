# Принципы синхронизации распределённого состояния

Уровень 2. Канон «как надо» для любых компонентов, работающих с общим
состоянием в etcd/DCS: воркеры, панель, Patroni-сады, тестовые фикстуры,
диагностические инструменты. Каждый принцип описан по схеме
**правило → почему критично → кейс → чем проверяется**. Новые компоненты
синхронизации проектируются по этим принципам (arch-first); реестр ошибок
пополняется по мере вскрытия новых ошибок использования — тем же форматом.

## 1. Принципы

| # | Принцип | Документ |
|---|---|---|
| S1 | **Один контур истины**: все участники работают с одним etcd, адрес задаётся явно | [01-truth-and-convergence.md](01-truth-and-convergence.md) §S1 |
| S2 | **Динамический конфиг DCS ≠ bootstrap**: владелец кластера конвергит динамический конфиг к канону каждый тик | [01-truth-and-convergence.md](01-truth-and-convergence.md) §S2 |
| S3 | **Инварианты внешних систем**: канонические значения в одном источнике, плавающие версии образов учитываются | [01-truth-and-convergence.md](01-truth-and-convergence.md) §S3 |
| S4 | **Ключи не вырождаться**: предикаты роли/принадлежности — по первоисточнику, etcd-ключ — маршрутизация и кэш | [02-predicates-and-mutations.md](02-predicates-and-mutations.md) §S4 |
| S5 | **Порядок мутаций**: клэйм или тик, фиксированный порядок записей, первый записавший — истина | [02-predicates-and-mutations.md](02-predicates-and-mutations.md) §S5 |
| S6 | **Журналы**: фазовые записи не затирают накопленные треки; журнал — не лог-история | [02-predicates-and-mutations.md](02-predicates-and-mutations.md) §S6 |
| S7 | **Транспортный флап ≠ смерть**: деструктив — только по положительному свидетельству; endpoint-failover etcd | [03-fault-tolerance.md](03-fault-tolerance.md) |
| S8 | **Свежесть инструментов**: тесты и диагностика запускают артефакт из текущего дерева | [04-tooling-and-investigation.md](04-tooling-and-investigation.md) §S8 |
| S9 | **Порядок расследования**: от стабильного к меняемому, факты до выводов | [04-tooling-and-investigation.md](04-tooling-and-investigation.md) §S9 |
| S10 | **Изменения применяются только при изменении**: опрос + локальный кэш + обработка различий | [05-delta-application.md](05-delta-application.md) |

Реестр вскрытых ошибок использования — [06-error-registry.md](06-error-registry.md).

## 2. Границы

Принципы описывают **общие правила работы с общим состоянием**; форматы
ключей и машин состояний конкретных доменов живут в их etcd-контрактах
([pgworker/00-etcd-contract.md](../pgworker/00-etcd-contract.md),
[kafkaworker/README.md](../kafkaworker/README.md),
[valkeyworker/README.md](../valkeyworker/README.md),
[s3worker/README.md](../s3worker/README.md),
[etcdworker/00-etcd-contract.md](../etcdworker/00-etcd-contract.md),
[backups/05-etcd-contract.md](../backups/05-etcd-contract.md)) и не
дублируются здесь.

## 3. Применение

- Новый компонент синхронизации проектируется по этим принципам; отклонение —
  явное решение владельца проекта, зафиксированное в его каноне.
- Диагностика сбоев синхронизации идёт по [S9](04-tooling-and-investigation.md) —
  от стабильного уровня к меняемому.
- Расхождение кода с принципами — блокирующее замечание ревью; новая
  вскрытая ошибка использования дописывается в
  [реестр](06-error-registry.md) с привязкой к принципу и закрытием.
