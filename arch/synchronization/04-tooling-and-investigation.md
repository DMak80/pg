## S8. Свежесть инструментов: тестируется собранное из текущего кода

**Правило.** Тесты/диагностика запускают артефакт, собранный из текущего
дерева (автосборка в фикстуре до старта контура), отказ сборки и отсутствие
артефакта — fail-fast. Явный opt-out (env-лазейка) — только для
целенаправленных исторических прогонов (бисект), никогда по умолчанию.

**Почему критично.** Устаревший «зелёный» бинар скрывает регрессию:
фикстура молча запускает старый артефакт, тесты проходят, дефект растёт
неделями.

**Кейс.** `E2eFixture.EnsureAppDllAsync`: автосборка Release до
docker-очистки; `PGW_TEST_E2E_NOBUILD=1` — лазейка бисекта; отсутствие dll
при NOBUILD — ApplicationException с командой сборки.

**Проверка.** Юнит на fail-fast-ветки; правило мерж-гейта в AGENTS.md
(docker-E2E на свежем Release для задач, трогающих код воркеров).

## S9. Порядок расследования: от стабильного к меняемому

**Правило.** Диагностика сбоев синхронизации идёт строго снизу вверх, каждый
уровень — с фиксацией фактов до выводов:

1. **Контур**: все смотрят в один etcd (S1) — сверка фактических endpoints.
2. **Регистрация**: сущности записаны корректно (порты/адреса/роли —
   динамические порты против фактических mapped, S4).
3. **Связность**: участники видят друг друга (репликация, REST-статусы
   членов, кворум).
4. **Детерминизм**: мутации по тикам — одинаковый порядок, опора на первый
   элемент изменения (S5); где разрыв — кто первый не увидел/не записал.

**Почему критично.** Расследование «сверху» (симптом теста) ловит
следствия, а не причину: flipped=False в тесте был следствием трёх
независимых причин на разных уровнях (контур-конфиг DCS, вырожденный
предикат, флап готовности). Каждая «починка следствия» стоила прогона и
маскировала следующую причину.

**Кейс.** Чек-лист 1–4 вскрыл: динамический конфиг ttl=20 (уровень 1–2),
503 Patroni из неготовности (уровень 3), недетерминированные ожидания
тестов (уровень 4). Фиксы по уровням закрыли всё; финальный бюджет failover
≤5 с подтверждён замерами ~3,1–3,2 с.

**Проверка.** Журнал расследования фиксирует факты уровнями; вывод
«механизм словами» — до правки кода (гейт задачи).
