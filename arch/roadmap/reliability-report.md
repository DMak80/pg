# Живой отчёт надёжности: что сделано, что осталось, влияние на характеристики

Статус-документ трека [reliability.md](reliability.md). Создан по аудиту
надёжности 2026-09-28 (HA / бэкапы / control-plane / наблюдаемость).

**Правило актуальности** (симметрично мерж-гейту трека): закрытие задачи
тем же мерж-коммитом (1) снимает пункт из reliability.md и (2) переносит
строку из «Осталось» в «Сделано» здесь — с merge-коммитом и правкой сводки
по затронутой характеристике. Отчёт не может рассинхронизироваться с
roadmap: правятся вместе. Появление новой задачи трека — дописывается в
«Осталось» тем же коммитом, что и пункт в reliability.md.

## Целевые характеристики

| Метка | Характеристика | Суть |
|---|---|---|
| **D** | Отсутствие потери данных | RPO, восстановимость, защищённость копий |
| **R** | Быстрая самовосстанавливаемость | RTO, автоматика без оператора, устойчивость control-plane |

## Сводка по характеристикам (обновляется при закрытии задач)

### D — отсутствие потери данных

Ядро добротное: непрерывный WAL-стриминг с подтверждением по доставке
(собственный приёмник подтверждает слот только после фактического put
сегмента в S3) и двойной архивацией мастер+sync-standby в один префикс
(t27): RPO = 0 подтверждённых транзакций при потере любой одной машины;
граница — незакоммиченный хвост после последнего sync-подтверждения
(вне RPO durable). Суточные полные + verify (манифест SHA256 + цепочка
WAL) + restore latest/PITR/DR + GFS-ретенция + самолечение
BROKEN-цепочки; failover мастера в sync-режиме Patroni с ускорением
воркером ≤5 с; восстанавливаемость через точку TLI-переключения
(смешанный сегмент failover, побайтово подтверждённый) доказана E2E
в обоих режимах цели — latest и target_time на одной WAL-цепочке.
Kafka вне подсистемы бэкапов по зафиксированному решению 2026-09-28:
данные невосстановимы из бэкапов, RPO держится RF×minISR (arch/16 §6,
arch/19 §1).
Режим «долговечность-vs-доступность» — per-cluster выбор (t06):
`synchronous_mode_strict` в config кластера (отсутствие поля = true),
bootstrap несёт значение в bootstrap.dcs, живые кластеры приводит
конвергенция DCS; strict-кластер без sync-standby блокирует запись —
потеря «хвоста» при failover исключена явным выбором оператора.
DR-источник защищён от сиротского TTL (t04): сирота с валидным полным
(`full/<id>/backup_manifest`) не удаляется автоматикой никогда —
автоправило sweeper'а; операторская защита — hold/unhold, осознанная
потеря — только заявка delete с confirm (API воркера + панель, алерт
различает 4+1 судьбу сироты); `OrphanTtlSec` чистит только незащищённых
(arch/19 §4).
Восстановимость доказывается автоматически — RestoreDrillProcess по расписанию
(`policy.drill.interval_days`) разворачивает бэкап во временный изолированный
контур и контролирует выход из recovery, снос контура — доводимая фазой
cleaning при любом исходе (t02-restore-drill, arch/19 §3.6).
Контроль-плейн восстановим из S3: каждый etcd-слепок (плановый 6 ч +
внеочередные в точках изменений) выгружается в бэкап-бакет (префикс `etcd/`,
пары db+meta с sha256, ретенция 28 пар), восстановление — runbook-канон:
ручная sha256-сверка — барьер, `etcdutl snapshot restore` верифицирует
(t08-etcd-snapshot-export).

Открытые разрывы: бэкапы не шифрованы и в единственном хранилище
(`t01`, `t03`); сокращение окна пересъёма — инкрементальные полные
(`t18`) и автозакрытие потерянных слотов (`t19`).

### R — быстрая самовосстанавливаемость

Автоматика богатая: failover ≤5 с, rebuild реплики 90 с (кворум-гварды),
takeover воркера ≤15 с, идемпотентность «по факту» во всех процессах,
конвергенция DCS-конфига и лимитов, самолечение цепочек бэкапов,
эвакуация мёртвого шарда (осознанное RPO = момент смерти, слияние
отвергнуто — решение 2026-09-28, arch/14 R4); контроль-плейн переживает
потерю хоста с etcd — каждый слепок (плановый 6 ч + внеочередные)
выгружается в S3 с доводкой тиком `RetryIntervalSec` при транзиенте,
восстановление — runbook-канон (t08).

Открытые разрывы: зависшие ротационные заявки без таймаутов (`t10`);
Swarm без ускоренного failover (`t11`); нет watchdog зависших циклов
(`t12`); сценарии отказа хоста/DC не отработаны (`t20`, `t21`).

### N — надёжность / наблюдаемость

~50 правил алертов с Hint/Remedy (панель), HA/бэкапы/workers-панели,
healthz с секциями. Слабое место — «молчание»: без внешней нотификации
и истории деградация невидима, если никто не смотрит в панель; метрики
реальных нод не собираются.

Открытые разрывы: нотификации и истории нет (`t13`); бэкапные статусы не
в метриках (`t14`); прод-ноды недоскрейпимы (`t15`); expiry сертификатов
не мониторится (`t16`); RPO/RTO-чисел оператору нет (`t17`);
Patroni REST без TLS/аутентификации (`t22`).

## База: что уже сделано (срез 2026-09-28)

Правится при существенных изменениях подсистем (не привязано к задачам
трека — история изменений в git).

| Подсистема | Оценка | Ключевой факт |
|---|---|---|
| HA PG: failover мастера | высокая | Patroni sync-режим + ускорение воркером по факту смерти лидера, бюджет ≤5 с, жёсткий ассерт E2E (AC5); sync-режим per-cluster — `synchronous_mode_strict` (t06) |
| HA PG: rebuild реплик | высокая | авто-rebuild молчащей ноды за 90 с при кворуме, гварды от слепых пересозданий (S7) |
| Эвакуация мёртвого шарда | средняя | автоматика E0–E4 есть; RPO = момент смерти — осознанно, слияние отвергнуто 2026-09-28 (arch/14 R4) |
| Бэкапы: полные+WAL+verify | высокая | непрерывный стриминг, verify манифеста/цепочки, GFS-ретенция, самолечение BROKEN |
| Restore (latest/PITR/DR) | высокая | покрыт E2E; регулярный drill есть — RestoreDrillProcess по расписанию (`policy.drill.interval_days`, t02), второго хранилища нет |
| Шифрование бэкапов | отсутствует | риск признан arch/19 §10 |
| Control-plane (код) | высокая | stateless-воркеры, всё в etcd, идемпотентность по факту, takeover доказан E2E kill-тестами |
| Деплой-уровень | средне-высокая | воркеры по два инстанса (t07: клэймы мигрируют ≤15 с, надзор без SPOF); etcd 3-узловой HA-контур (`t09`) |
| etcd-обслуживание | средне-высокая | снапшоты 6 ч + внеочередные, каждый слепок выгружается в S3 (t08: префикс `etcd/`, пары db+meta sha256, ретенция 28 пар, статус-ключ с доводкой `RetryIntervalSec`), восстановление — runbook-канон (ручное) |
| Надёжность Kafka | средняя | RF/minISR converge, тома неприкосновенны, drain перед демонтажом; бэкапов нет — позиция зафиксирована (невосстановимо из бэкапов, RPO = RF×minISR, arch/16 §6); USR — только наблюдение |
| Valkey | по назначению — ок | кеш by design: nodes=1, без персистентности; не для не-кеш данных |
| Ротации секретов/CA/TLS | высокая | пароли/CA без простоев (окна двойного доверия), миграция plain→TLS; секреты в etcd открыто — закрывается `t02-external-secret-manager` (pgworker-трек) |
| Алерты/панель | средняя | ~50 правил с Hint/Remedy; нотификаций наружу и истории нет |
