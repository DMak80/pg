# Roadmap: подсистема бэкапов шардов

Отложенные задачи подсистемы бэкапов PG-шардов. **PgWorker — хозяин
бэкапов**: он сам создаёт, ретраит/пересоздаёт при неудаче, чистит лишнее,
обрабатывает пограничные случаи и сигнализирует в алертинг панели — что
сломалось и какие действия предприняты. Канон подсистемы —
[../backups/README.md](../backups/README.md); контекст сервиса —
[../pgworker/README.md](../pgworker/README.md).

Порядок: канон → полный бэкап → online-архивация WAL → проверки →
восстановление → ретенция → супервизор-цикл над всем → панель управления
хранилищем (S3).

## Задачи

- **t15-wal-partial-delta** ← t14-backup-wal-partial — инкрементальная
  доставка RPO-хвоста вместо перезаливки всего префикса (экономия трафика
  и ресурса SSD хранилища). Решения владельца: (1) дельты-куски с
  байтовыми диапазонами в имени (`wal/<segment>…partial_<start>_<end>`),
  выкладка параллельно, границы кусков — только по целым WAL-записям
  (любая склейка валидна); (2) приоритет пересечений диапазонов:
  свежая инкарнация → роль master над replica (метка роли на момент
  выкладки) → более ранний start → детерминированный tie-break; байты
  одного диапазона от разных нод при исправной репликации совпадают —
  несовпадение в пересечении при компакции = алерт (порча невозможна у
  исправного PG); (3) дыра в середине покрытия — фолбэк последней
  надежды, только когда живой источник/полный бэкап недоступны:
  восстановить всё ДО дыры, после дыры отбросить (+алерт); «хвост не
  дописан» — не дыра, берётся закрытое покрытие; (4) компакция
  base+delta: раз в `Wal:PartialCompactIntervalSec` (настройка, дефолт
  1 ч) pgNode перезаливает кумулятивный префикс одним объектом, если
  был инкремент; инкременты ниже базы/финала чистит wal-sweeper
  (pgWorker); (5) проверки целостности: сверка start/end из имени с
  фактическим размером объекта S3; Content-MD5 на put дельт (транспорт
  отвергает битое); checksum куска в имени как страховка от порчи при
  хранении — закрыть в спеке; подтверждение слота и RPO-инварианты —
  по-прежнему только по финалам (дельты — ускоритель доставки хвоста,
  не источник гарантий); dual-gate пампа (минимальный прирост ИЛИ
  максимальный возраст) поверх дельт; листинги с пагинацией; E2E:
  дыра/конфликт пересечений/failover источника между дельтами.
