# Roadmap: подсистема бэкапов шардов

Отложенные задачи подсистемы бэкапов PG-шардов. **PgWorker — хозяин
бэкапов**: он сам создаёт, ретраит/пересоздаёт при неудаче, чистит лишнее,
обрабатывает пограничные случаи и сигнализирует в алертинг панели — что
сломалось и какие действия предприняты. Канон подсистемы —
[../19-backups.md](../19-backups.md); контекст сервиса —
[../14-pgworker.md](../14-pgworker.md).

Порядок: канон → полный бэкап → online-архивация WAL → проверки →
восстановление → ретенция → супервизор-цикл над всем → панель управления
хранилищем (MinIO).

## Задачи

- **`t04-backup-verify`** — проверки полных бэкапов: `pg_verifybackup`
  (checksum) + проверка полноты WAL-цепочки до точки бэкапа, статус
  проверки в etcd; по политике — периодическая проверка оставшихся
  бэкапов, алерт при невалидном.
- **`t05-backup-restore`** — восстановление шарда из бэкапа: полный бэкап
  + накат WAL (PITR, в т.ч. на точку времени), операция по команде через
  PgWorker (пересоздание ноды/шарда из бэкапа), runbook-сценарии (полная
  потеря ноды, порча данных, восстановление в новый кластер). Критерий:
  на dev-станде кластер уничтожается и поднимается из бэкапов с
  проверкой данных.
- **`t06-backup-retention`** — управление бэкапами и местом: схема
  оставления полных бэкапов 1д/7д/1мес (GFS), удаление устаревших
  полных; удаление ненужных WAL-сегментов — старше стартовой точки
  старейшего оставшегося полного бэкапа; защита от переполнения
  хранилища (квоты/пороги, алерт при нехватке места, запрет удалять
  последний валидный бэкап).
- **`t07-backup-supervisor`** — супервизор-цикл PgWorker над всей
  подсистемой (reconcile желаемого состояния бэкапов из etcd):
  сам решает — что создать/пересоздать (неуспех по любой причине), что
  удалить (лишнее место не сжирает), сверяет фактическое содержимое
  хранилища с etcd-состоянием (зависшие/осиротевшие бэкапы и WAL);
  пограничные случаи — удаление/эвакуация шарда (судьба его бэкапов),
  смена мастера посреди операций, рестарт PgWorker посреди бэкапа
  (возобновление/пересоздание); каждый сбой и предпринятое действие —
  алерт в панель (какие действия предприняты). ← `t04-backup-verify`,
  `t05-backup-restore`, `t06-backup-retention`.
- **`t08-backup-minio-panel`** — панель управления MinIO в AdminPanel
  (MinIO — объектное хранилище бэкапов; вариант «объектное
  хранилище» закрыт каноном arch/19 §5): грань
  «Хранилище бэкапов» — подключение к MinIO (endpoint/ключи из секретов),
  просмотр бакетов/объектов (полные бэкапы, WAL-сегменты), занятое
  место/квоты, health MinIO (диски); сверка фактического содержимого
  хранилища с etcd-состоянием бэкапов (осиротевшие объекты — глазами
  человека, t07 делает это автоматически).
