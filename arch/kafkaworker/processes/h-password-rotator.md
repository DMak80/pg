# H. PasswordRotator (фазы A/B/C — без окна недоступности; роли app|admin)

Уровень 4. Ротация per-cluster паролей app и admin. Функция —
[04-security.md](../04-security.md) §4; политика экспирации —
[08-operability.md](../08-operability.md) §3.

Заявка `/kafkaworker/rotations/<C>` (app) или
`/kafkaworker/admin_rotations/<C>` (admin); NEW = генерация (32 симв).
Ротируются независимо (механизм один):

- **A)** rolling пересоздание контейнеров брокеров по одному (ждать
  возврата в ISR) с JAAS из ДВУХ пользователей роли (OLD+NEW: `user_app`+
  `user_app2` либо `user_admin`+`user_admin2`) — все клиенты работают
  со OLD;
- **B)** ОДНА txn: `[compare value(<роль>_password)==OLD][put NEW; del
  заявки]` — клиенты перечитывают etcd и переподключаются с NEW;
- **C)** rolling пересоздание с JAAS только NEW (снятие OLD-пользователя).

Guard'ы: кластер не поднят (нет endpoints/кредов) или не отвечает
DescribeCluster (слепой преф-чек проходится каждым тиком, в т.ч. посреди
фазы A) → journal `waiting-cluster`; **открытое окно CA-ротации
[K](k-ca-rotator.md)** (staging `ca_next_*` жив) → journal
`waiting-ca-window` (передержка — rolling-и не смешиваются; окно доиграет K
этим же/следующими тиками, затем H продолжит). Живая, но НЕ начатая
ca-заявка H НЕ гейтит (приоритет H перед K): при обеих живых заявках H
доигрывает свою (del заявки в фазе B), затем K исполняет свою — взаимное
ожидание двух заявок (дедлок) невозможно. Возрастная самозачистка — в
waiting-исходе ТОЛЬКО при гварде «не начато»
([08-operability.md](../08-operability.md) §3): журнал роли показывает
незавершённую мутацию (`phase-a`/`rotated-commit`/`phase-c` — заявка уже
раскатывается, слепота кластера в середине A — передержка) → чистый waiting
без экспирации; стагнация начатой ротации — зона панельного алерта
`kafka-rotation-stale`.

Waiting-фазы журнала пишутся только при живой заявке: afterCommit-хвост
(заявка снята фазой B, журнал `rotated-commit`/`phase-c`, финал не достигнут)
в точках ожидания (окно CA, слепой снапшот, слепой преф-чек) журнал не
перезаписывает — тихая передержка тика; маркер мутации — единственный
носитель возобновляемости фазы C, его затирание waiting-фазой делало бы
финал недостижимым (ротация-«зомби»). Стагнация хвоста наблюдаема по
застывшей фазе (`updated_unix` не растёт) — зона панельного алерта
`kafka-rotation-stale`.

Отказ между фазами безопасен (оба креда валидны; перезапуск идёт с
записанной фазой из journal). Окно «часть брокеров знает только NEW»
невозможно по построению. Снапшоты P12 «до» (старт ротации) и «после»
(финал; вместе с ним — put `ticket_outcomes/<C>` outcome=done). Битая
заявка — мусор: del с journal (панель до того получает 409 «уже запрошена»).
Уведомление в UI-модалке: выполнять в тихое окно (rolling-рестарты). Ротация
admin не трогает app-кред и inter; воркер переключается на NEW-кред клиента
после B (следующий снапшот-тик).
