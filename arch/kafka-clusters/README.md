# Kafka-кластеры — контракт домена

Уровень 2. Контракт etcd Kafka-домена: контроль-плейн кластеров `/kafka/`,
координация воркера `/kafkaworker/` и клиентский дискавери. Уровень 3 —
разделы контракта (`01`–`06`); исполнительная сторона —
[kafkaworker/README.md](../kafkaworker/README.md).

## 1. Назначение домена

Приложение читает адреса, SASL-креды и **реестр топиков** исключительно
отсюда — полная аналогия pg dsn/`app_password`/routing
([pg-clusters/11-buckets.md](../pg-clusters/11-buckets.md) §2).

**Разделение ответственности**: панель AdminPanel **декларирует** кластер
через HTTP API воркера, **KafkaWorker исполняет**
([kafkaworker/README.md](../kafkaworker/README.md)); в etcd домена пишет
только воркер.

## 2. Имена

- **Кластер `<C>`** — `^[a-z][a-z0-9_]{0,62}$` (как pg; без дефиса).
- **Брокеры `broker1..brokerN`** — имя генерирует панель (`broker<max+1>`,
  ≤ 9).
- **Топик `<T>`** — валидное Kafka-имя, не начинающееся с `__`
  (internal-топики Kafka в реестр не попадают).

## 4. Свойства, на которые опираются все разделы

- **Один общий etcd-контур** со стендом pg
  ([synchronization/README.md](../synchronization/README.md) S1);
  динамика покрывается тиками воркера (5 с) и панели (3 с) — watch не
  используется ([01-transport.md](01-transport.md) §1).
- **Декларативная модель**: отсутствие `config.state` = Active-кластер;
  `NOT_INITIALIZED`/`TO_REMOVE` — заявки панели ([02-keys.md](02-keys.md) §1).
- **Факт против заявки**: реестр топиков — факт Kafka, `desired` — заявка
  панели; снятие заявки выполняет воркер ([03-topics.md](03-topics.md)).
- **Толерантность парсеров**: битый JSON, неизвестные ключи и новые поля не
  роняют читателя ([06-fault-tolerance.md](06-fault-tolerance.md)).
