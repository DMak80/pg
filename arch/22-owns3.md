# 22. ownS3: собственное S3-хранилище ★

**ownS3** — собственное S3-совместимое объектное хранилище на C#/.NET 10
(проекты `src/OwnS3.*` монорепо); **целевая замена MinIO** подсистемы
бэкапов после приёмки t39: клиенты переключаются env-endpoint'ом, код
клиентов не меняется. Целевые клиенты — AWS SDK .NET подсистемы бэкапов
([19-backups.md](19-backups.md)) и `mc`. Критерий правильности любой
грани — **стандарт S3 API**: поведение, которое ожидают стандартные
S3-клиенты.

## Принцип: стандарт S3, а не копия MinIO

**MinIO — пример реализации, а не образец для копирования.** Полная
копия MinIO не делается — API реализуется по стандарту S3. Исходники
MinIO ([../minio](../../minio), Go) — точечный референс «как этот
вопрос решает работающая реализация», без переноса его механики
целиком. Единственное, что берётся у MinIO сознательно, — раскладка
хранения на диске: single-drive xl-раскладка (бакеты — каталоги,
объект — каталог с `xl.meta` + `<dataDir-uuid>/part.N`); побайтовая
совместимость формата `xl.meta` не требуется. Служебный контур —
**`.owns3.sys`**: имена служебных сущностей ownS3 задаёт собственный
канон.

## Границы начального этапа

- **22 операции** API (объекты/листинги/бакеты/multipart) — полный
  контракт в главе 02.
- Бакеты без versioning (`ListObjectVersions` — unversioned-семантика).
- Single-drive без erasure coding и репликации.
- Обращение к вне-наборным граням (сабресурсы объекта, конфигурации
  бакета, S3-Express, notification, select) — единый канонизированный
  отказ (глава 02).
- **Path-style only, HTTP-only**: виртуальные хосты не поддерживаются,
  TLS — задача трека.
- Последующие этапы (erasure coding, репликация) — трек.
