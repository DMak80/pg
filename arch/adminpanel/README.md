# arch/ — архитектура AdminPanel

Контракт проекта: **источник истины** о том, что строится. Код не должен
противоречить этим документам; изменение поведения = изменение документа (тем же
PR/коммитом).

Инспектируемая система — шардированные HA-кластеры PostgreSQL из репозитория
`../pg` (Patroni + etcd + бакетное шардирование). AdminPanel — **строго
read-only**: ни одной операции записи в etcd/PG, кроме собственной сессионной
cookie.

## Ключевые решения (кратко)

1. **Единственное обязательное подключение к данным — etcd** (список
   endpoint'ов в настройках). Кластеры, шарды, реплики, бакеты — только из
   префиксов `/clusters/` и `/service/`. Live-пробы (Patroni REST `:8008`, SQL
   через Npgsql по DSN из etcd) — опциональные, включаются настройкой.
2. **Снапшот в памяти**: фоновый refresher каждые N секунд строит неизменяемый
   снапшот (`EtcdSnapshot`), API отдаёт его мгновенно. Запросов к etcd «на
   каждый HTTP-запрос» нет.
3. **etcd-клиент — HTTP JSON gateway** (`/v3/*`, base64-ключи), без gRPC;
   тот же механизм используют сайдкары инспектируемой системы.
4. **Backend .NET 10** по конвенциям референса `../Puzzle`: Minimal API,
   attribute-DI (`[InjectAs*]`, `[Config]`), CQRS (только queries) + `Result`,
   модульная композиция, `.slnx`, CPM.
5. **Frontend React + Vite + TypeScript** (Mantine, TanStack Query), собирается
   в `wwwroot` и раздаётся тем же ASP.NET Core; обновление — polling API
   (без WebSocket).
6. **Auth — cookie-сессия**, логин/пароль админа из настроек (без БД
   пользователей).
