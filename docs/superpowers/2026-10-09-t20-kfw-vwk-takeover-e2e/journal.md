# Журнал t20-kfw-vwk-takeover-e2e

2026-10-09. Задача из трека надёжности (P4, влияние R): host-kill docker-E2E
для KafkaWorker/ValkeyWorker. По ходу переросла в двухсоставную — решение
пользователя «нужный результат, а не кипа задач».

## Хронология решений

- **Ревизия 1 спеки** (чисто тестовая): жертва Valkey — ротация CA
  (nodes>1 запрещён v1-API: `ValkeyLimits.MaxNodes = 1`); жертва Kafka —
  provisioning 3-брокерного кластера; kill ДЕРЖАТЕЛЯ клэйма (усиление к
  PgWorker-эталону: резолв claims→api→порт, matched==1 с дампом).
- **Ревизия 2**: точные кейс-маркеры по классам (фильтр `~Takeover` цепляет
  7 чужих); kill держателя; roadmap-гейт трека.
- **Ревизия 3 (двухсоставная)**: разбор падения wait-clean упорного прогона
  (артефакты 6144da62) вскрыл корень: движковый helper `vwk-tls-writer-*`
  (sleep 120, bind TLS-тома) переживает kill создателя → демонтаж X1 стоит
  на 409 volume-in-use ~100 с. Бюджеты двигать запрещено (приказ) → решение
  пользователя: env-TLS у ValkeyWorker ВНУТРИ задачи (модель Kafka: PEM в
  env ноды + cmd-обёртка старта; том и helper-механика демонтированы,
  arch-first arch/21; миграция живых кластеров надзором).
- **СТОП Р2 №1** (прогон 182646, диагностический по согласованию): ротация
  CA в env-модели завершилась за ~0,2 с (R без helper-записи тома) — окно
  kill исчезло. Решение пользователя: жертва Valkey = ДЕМОНТАЖ (X0–X3).
- **СТОП Р2 №2** (прогон e055e1e0): survivor доигрывает демонтаж одним
  тиком <0,5 с — journal-полл 500 мс неприменим (120 поллов ни одного
  попадания). Решение пользователя: I2 по построению (kill-до-X0 +
  единственность survivor + терминальная чистота) + документальный
  лог-факт «deprovision {C}» от survivor (жертва до X0 убита — вхождений 0).
- **Попутный факт хоста**: внешняя чистка /tmp стирает каталоги
  /tmp/pgw-e2e-artifacts-* — артефакты E2E-прогонов переключены на
  TMPDIR вне /tmp (~/pgw-diag-t20/); телеметрия сохраняется.
