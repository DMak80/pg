# Отказоустойчивый PostgreSQL-кластер (Patroni + Spilo + etcd + HAProxy)

Воспроизводимый рецепт развёртывания HA-кластера PostgreSQL на 3 (или 4) физических
хостах в Docker. У каждой ноды своё локальное хранилище — без общего диска
(NFS/SAN). Документация написана так, чтобы по ней мог настроить кластер кто угодно,
включая автора в будущем.

## Стек

- **PostgreSQL** — один primary (read+write) + реплики (read-only), streaming replication (WAL over TCP).
- **Patroni** — менеджер репликации и автоматического failover.
- **Spilo** — готовый образ Zalando (PostgreSQL + Patroni в одном контейнере).
- **etcd** — распределённое KV-хранилище (DCS): состояние кластера, выборы лидера, кворум.
- **HAProxy** — единая точка входа: порт `5432` → мастер, `5433` → реплики.

Проверено на Patroni 4.x + Spilo 3.3 + PostgreSQL 16 + etcd 3.5 + HAProxy 2.8;
бакетный слой — на PostgreSQL 18.4.

## Архитектура

```
etcd x3 ── DCS: кто лидер, конфиг кластера (кворум 2/3)
   ▲
Patroni x3 ── управляет локальным PostgreSQL, держит лидера
   ▲
PostgreSQL x3 ── 1 master (RW) + 2 replicas (RO)
   ▲
HAProxy ── 5432 → master, 5433 → replicas
```

## Возможности

- Автоматический failover при потере ноды и защита от split-brain (кворум etcd).
- Плановая смена мастера (switchover), бэкапы, пересоздание ноды.
- Схема на **3 ноды** и опционально на **4 ноды** (переживает двойной отказ).
- Опциональный **бакетный шардинг**: кластер создаётся с фиксированным числом
  бакетов-схем (константа), распределённых поровну по шардам; шарды добавляются
  (пустыми) и удаляются (только пустые); любой бакет **онлайн** переезжает между
  шардами без простоя записи. Один etcd обслуживает несколько независимых
  шардированных кластеров.
